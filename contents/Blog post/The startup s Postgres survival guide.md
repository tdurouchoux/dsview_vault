## Summary

The guide provides practical advice for managing Postgres at scale, focusing on schema design, query optimization, and advanced features. Key points include:

- **Schema Design**: Use identity columns or UUIDs for primary keys, always use `timestamptz`, and prefer foreign keys with cascading deletes for low-volume tables. Avoid excessive normalization if it impacts query efficiency.
- **Query Optimization**: Ensure queries use indexes (primary keys, unique constraints) to avoid slow sequential scans. Compound indexes should align with `ORDER BY` clauses.
- **Write Queries**: Keep transactions short, avoid unnecessary row locks, and use `CREATE INDEX CONCURRENTLY` to prevent write blocking.
- **Migrations**: Prefer additive migrations and use transactions for rollback safety. Avoid `ALTER TABLE` operations that block writes.
- **Connection Management**: Use connection poolers (e.g., pgbouncer or pgxpool) to reduce overhead and avoid connection storms.
- **Query Planner**: Understand that the planner relies on table statistics. Use `EXPLAIN ANALYZE` to debug slow queries and monitor autovacuum settings to prevent bloat.
- **Advanced Features**: Utilize `FOR UPDATE SKIP LOCKED` for job queues, partitioning for time-series data, and batched backfills for large migrations to avoid long-running transactions.
- **ORM Considerations**: ORMs may limit optimizations; consider tools like `sqlc` or `TypedSQL` to write raw SQL when needed.

The guide emphasizes iterative schema development, efficient query design, and proactive monitoring to maintain Postgres performance under load.
